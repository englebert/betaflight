# INA226 current and voltage monitor

Support for the TI INA226 bidirectional current/power monitor as a Betaflight
voltage **and** current meter source, added for the LittleBee 1.0 build on a
JHEMCU GF30F722-ICM (`JHEF7DUAL`, STM32F722).

## Why

On this airframe the flight controller is fed from a boost converter holding a
stable 12 V, because the board browns out when the 2S pack drops below about
6.5 V. That makes the board's own VBAT divider useless as a pack monitor — it
reads the regulated 12 V rail, not the battery. An INA226 with a 0.001 Ω shunt
sits on the pack side of the wiring and supplies both readings instead.

## Build

The feature is compiled in by the board config, not by a runtime feature flag.

```bash
cd /home/englebert/Projects/NaMiQuad/LittleBee-1.0/betaflight
make CONFIG=JHEF7DUAL_INA226 CONFIG_DIR=$PWD/configs_local -j$(nproc)
```

Output: `obj/betaflight_<version>_STM32F722_JHEF7DUAL_INA226.hex`

One-time setup on a fresh clone:

```bash
make configs           # fetch the src/config submodule
make arm_sdk_install   # install the pinned gcc 13.3.1 into tools/
```

Do not pass `CONFIG_DIR=` to `make configs` — it would try to `git pull` inside
`configs_local` and fail.

### Enabling it in a config

`configs_local/configs/JHEF/JHEF7DUAL_INA226/config.h`:

```c
#define USE_INA226
#define INA226_I2C_INSTANCE            I2CDEV_1
#define INA226_I2C_ADDRESS             0x40
#define INA226_DEFAULT_SHUNT_MICROOHMS 1000   // 0.001 ohm

#define DEFAULT_VOLTAGE_METER_SOURCE VOLTAGE_METER_INA226
#define DEFAULT_CURRENT_METER_SOURCE CURRENT_METER_INA226
```

`USE_INA226` is silently dropped on a build without `USE_I2C`
(see `src/main/target/common_post.h`).

## Wiring

On the GF30F722-ICM, I2C1 is **PB6 (SCL) / PB7 (SDA)**, shared with the
barometer.

| INA226 pin | Connect to |
|---|---|
| `VS`      | FC 5 V |
| `GND`     | FC ground (common with the pack) |
| `SCL`     | PB6 |
| `SDA`     | PB7 |
| `VBUS`    | Pack positive, upstream of the shunt |
| `IN+`     | Shunt, pack side |
| `IN-`     | Shunt, load side |
| `A0`,`A1` | GND for address 0x40 |

Most INA226 breakouts carry their own I2C pull-ups, which end up in parallel
with the ones already on the flight controller for the barometer. If the bus
misbehaves after fitting the sensor, that is the first thing to check.

### Addresses

`A1`/`A0` select one of sixteen addresses, 0x40–0x4F (64–79 decimal):

| A1 | A0 | Address |
|---|---|---|
| GND | GND | 0x40 (64) |
| GND | VS  | 0x41 (65) |
| GND | SDA | 0x42 (66) |
| GND | SCL | 0x43 (67) |
| VS  | GND | 0x44 (68) |

…and so on through `SCL`/`SCL` at 0x4F.

## CLI settings

The compiled-in defaults already match this airframe, so a plain `defaults`
gives you a working configuration. Change these only if your hardware differs.

### Meter selection

| Setting | Values | Default here |
|---|---|---|
| `battery_meter` | `NONE`, `ADC`, `ESC`, `INA226` | `INA226` |
| `current_meter` | `NONE`, `ADC`, `VIRTUAL`, `ESC`, `MSP`, `INA226` | `INA226` |

### Sensor configuration

| Setting | Type | Range | Default | Meaning |
|---|---|---|---|---|
| `ina226_i2c_device` | uint8 | 0–4 | `1` | I2C bus in CLI numbering; 1 = I2C1. 0 disables. |
| `ina226_i2c_address` | uint8 | 0–119 | `64` | 7-bit address, decimal. 64 = 0x40. |
| `ina226_shunt_resistance` | uint16 | 50–65535 | `1000` | Shunt value in **micro-ohms**. 1000 = 0.001 Ω. |
| `ina226_vbat_scale` | uint16 | 500–2000 | `1000` | Bus voltage trim in 1/1000ths. 1000 = ×1.000. |
| `ina226_current_offset` | int16 | −32000–32000 | `0` | Zero-current offset in centiamps, added after scaling. |
| `ina226_averaging` | lookup | `1`,`4`,`16`,`64`,`128`,`256`,`512`,`1024` | `4` | Samples the device averages internally. |
| `ina226_current_invert` | lookup | `OFF`, `ON` | `OFF` | Negate the shunt reading for a reversed shunt connection. |

Example, for a 0.5 mΩ shunt on a second INA226 at 0x41:

```
set ina226_i2c_address = 65
set ina226_shunt_resistance = 500
save
```

## Calibration

Do this on the bench, on USB, before flying.

**1. Check it is detected.** With the pack connected, `status` should show a
sane pack voltage and Configurator's Power & Battery tab should track it. A
voltage stuck at 0.00 V means the device did not answer at boot — see
[Troubleshooting](#troubleshooting).

**2. Voltage.** Measure the pack with a multimeter, compare to the reported
voltage, then:

```
ina226_vbat_scale = 1000 × (measured / reported)
```

For example, reported 8.31 V against a measured 8.40 V gives
`1000 × 8.40 / 8.31 ≈ 1011`.

**3. Current direction.** Apply a known load. If the reported current is
negative, set `ina226_current_invert = ON` rather than resoldering.

**4. Current magnitude.** With a load drawing a known current:

```
ina226_shunt_resistance = old × (reported / actual)
```

If the reading is 10% high, raise `ina226_shunt_resistance` by 10%. Adjusting
the resistance is the right knob here — it is exactly the quantity the maths
divides by, so it stays linear across the whole range.

**5. Zero offset.** With the motors stopped and the pack connected, if the
reading sits at a non-zero value, correct it with `ina226_current_offset` in
centiamps (e.g. a resting reading of 0.15 A → `set ina226_current_offset = -15`).
Do this last, after the scale is right.

`save` after each step.

## Verification and debugging

```
set debug_mode = CURRENT_SENSOR
save
```

Then watch in the Configurator's Sensors tab or in blackbox:

| Field | Meaning |
|---|---|
| `debug[2]` | Amperage, centiamps (unfiltered) |
| `debug[3]` | mAh drawn |
| `debug[4]` | Raw shunt register, signed, 2.5 µV per LSB |
| `debug[5]` | Bus voltage in 0.01 V |

`debug[4]` frozen at a constant value while the load changes points at the I2C
side rather than the maths.

## Behaviour and limitations

- **Detection happens once, at boot** (`batteryInit()`), by reading the
  manufacturer ID (0x5449) and the configuration register's reserved bits 14:12,
  which always read back as 0b100. The die ID register is deliberately not used:
  it sits at 0xFF, which Betaflight's I2C layer reserves as its "raw transfer,
  no register address" sentinel, so it cannot be addressed at all. **There is no
  retry.** If the
  INA226 does not answer at power-up, voltage and current read zero until the
  next power cycle.
- **A failed transfer keeps the previous reading** rather than dropping to
  zero. A zero would be interpreted as "no battery", which silently disables
  consumption alerts — worse in flight than a slightly stale voltage. The
  flip side is that a sensor that dies mid-flight leaves the last good value
  frozen on the OSD.
- **Range with a 1 mΩ shunt:** ±81.9 A (the device's ±81.92 mV shunt full
  scale), 2.5 mA resolution. Beyond that the reading clips. Bus voltage range
  is 0–40.96 V at 1.25 mV resolution, independent of the shunt.
- **Shunt dissipation** is I²R: 1.6 W at 40 A through 1 mΩ. Size the resistor
  accordingly.
- **Update rate** is about 30 full shunt+bus cycles per second, set by the two
  50 Hz battery tasks that drive the driver's state machine. The device's own
  conversion takes `averaging × 2.2 ms` — 8.8 ms at the default averaging of 4,
  so raising `ina226_averaging` much beyond 16 will make the sensor, rather
  than the tasks, the bottleneck.
- **The board's VBAT divider and ADC current sensor are unused** when the
  INA226 is selected. `vbat_scale`, `vbat_divider`, `vbat_multiplier`,
  `ibata_scale` and `ibata_offset` have no effect on the readings.
- Since the pack is always 2S here, `set force_battery_cell_count = 2` is worth
  setting so cell-count detection cannot guess wrong.

## How it works

The driver reads the shunt and bus voltage registers directly and does all
scaling in software. The device's calibration, current and power registers are
**not** used — going through the calibration register would quantise the
current to a coarser LSB than the 2.5 µV the shunt register already gives.

```
bus voltage (0.01 V)  = raw × 1.25 mV × ina226_vbat_scale / 10000
current     (0.01 A)  = raw × 2.5 µV × 100 / ina226_shunt_resistance
                        + ina226_current_offset
```

Transfers are **non-blocking**: a four-state machine
(`START_SHUNT` → `READ_SHUNT` → `START_BUS` → `READ_BUS`) using
`i2cBusReadRegisterBufferStart` and `i2cBusBusy`, the same pattern the
barometer uses. Both battery tasks call into it. A blocking read would have
spun roughly 120 µs inside a `TASK_PRIORITY_MEDIUM` task at 100 Hz, enough to
disturb an 8 kHz gyro loop, and it would have collided with the barometer
sharing I2C1. A busy bus simply defers the driver by one call.

At init the configuration register is written with the selected averaging,
1.1 ms conversion times for both channels, and continuous shunt+bus mode.

### Example
set battery_meter = INA226
set current_meter = INA226
set ina226_i2c_device = 1          # I2C1
set ina226_i2c_address = 64        # 0x40
set ina226_shunt_resistance = 1000 # micro-ohms, i.e. 0.001R
set ina226_vbat_scale = 1000       # 1.000x
set ina226_current_offset = 0      # centiamps
set ina226_averaging = 4           # 1/4/16/64/128/256/512/1024
set ina226_current_invert = OFF    # ON if current reads negative

### Source files

| File | Role |
|---|---|
| `src/main/drivers/ina226.{c,h}` | Device driver and I2C state machine |
| `src/main/pg/ina226.{c,h}` | Parameter group, `PG_INA226_CONFIG` = 570 |
| `src/main/sensors/voltage.{c,h}` | `VOLTAGE_METER_INA226` meter |
| `src/main/sensors/current.{c,h}` | `CURRENT_METER_INA226` meter |
| `src/main/sensors/battery.c` | Init and refresh dispatch |
| `src/main/cli/settings.{c,h}` | The `ina226_*` settings and averaging lookup |
| `src/main/target/common_post.h` | Drops `USE_INA226` without `USE_I2C` |
| `mk/source.mk` | Adds both new sources to the build |

Both meter sources are appended to their enums, so previously stored
`battery_meter` / `current_meter` values keep their meaning.
`voltageMeterRead()` and `currentMeterRead()` route `..._ID_BATTERY_1` to the
INA226 when it is the selected source, so MSP and the Configurator's Power tab
work unchanged.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Voltage and current both 0 | Not detected at boot. Check wiring, `ina226_i2c_device`, `ina226_i2c_address`; power-cycle (there is no retry). |
| Current always negative | `IN+`/`IN-` swapped. Set `ina226_current_invert = ON`. |
| Voltage right, current always 0 | `VBUS` connected but the shunt is not in the current path, or it is shorted. |
| Readings frozen | Sensor stopped answering; the driver holds the last value by design. Check `debug[4]` under `CURRENT_SENSOR`. |
| Barometer stops working after fitting the sensor | Bus loading — too many parallel I2C pull-ups, or wiring too long. |
| Current reads high and non-linear | Shunt sense wires tapped outside the resistor's sense points, picking up trace resistance. |
